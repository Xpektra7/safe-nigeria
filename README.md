# Solar-Powered Flood Warning System for Nigerian Communities

A real-time flood prediction system for Nigeria, using machine learning to provide early warnings at 3 different time horizons (1h, 3h, 6h).

## Overview

This project implements a complete ML pipeline that:

- Processes rainfall data from CHIRPS (Climate Hazards Group InfraRed Precipitation with Station data)
- Predicts flood probability at 1-hour, 3-hour, and 6-hour horizons
- Provides a REST API and web dashboard for real-time monitoring

## Current Status

What is working now:

- FastAPI backend is implemented with `/predict`, `/history`, `/health`, and `/reset`
- Prediction logic is implemented in `predictor.py`
- Trained model artifacts are present in the repository
- The frontend dashboard is wired to the API

What is still missing or needs cleanup:

- Public demo auth for `POST /predict` is not added yet
- Private hardware auth for `POST /ingest` is now a simple API key header, but you still need to issue/manage the key
- Deployment packaging is still manual

Bottom line: this is a working prototype for API-based flood prediction and dashboard history, not yet a production deployment.

### Target Location

- **State**: Bayelsa (NG006) - Niger Delta
- **Why Bayelsa**: Highest mean wet-season rainfall (~114mm/10-day), most flood-prone state in Nigeria

## Flood Thresholds

| Level  | Water Height | Alert       | Action                       |
| ------ | ------------ | ----------- | ---------------------------- |
| GREEN  | 0-369 cm     | Normal      | Monitoring only              |
| YELLOW | 370-399 cm   | Watch       | Community notified           |
| RED    | ≥400 cm      | Flood Alert | Emergency response triggered |

## Model Output

The system produces probability predictions for three horizons:

| Model          | Recall | Precision | Use Case                      |
| -------------- | ------ | --------- | ----------------------------- |
| flood_alert_1h | ~100%  | ~88%      | Imminent flood (≤1 hour)      |
| flood_alert_3h | ~89%   | ~75%      | Short-term warning (≤3 hours) |
| flood_alert_6h | ~67%   | ~87%      | Early warning (≤6 hours)      |

## Quick Start

### 1. Prerequisites

```bash
# Install dependencies (CPU-only, ~50MB)Binary alerts for each horizon (1h, 3h, 6h)
pip install fastapi uvicorn scikit-learn pandas joblib numpy matplotlib
```

### 2. Get Model Files

Run `floodsense_model_fixed (1).ipynb` in Google Colab and download these files:

```
models/xgb_flood_1h.joblib
models/xgb_flood_3h.joblib
models/xgb_flood_6h.joblib
models/thresholds.json
models/model_config.json
predictor.py
main.py
```

### 3. Run the API

```bash
uvicorn main:app --host 0.0.0.0 --port 8000
```

### Environment Variables

If you want `/history` and `/ingest` to use Postgres, set:

```bash
export DATABASE_URL="postgresql://<user>:<password>@<host>:5432/postgres"
export SUPABASE_HISTORY_TABLE="flood_readings"
export HISTORY_LIMIT="12"
export INGEST_API_KEY="<private-device-key>"
```

### 4. Test the API

```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"water_level": 3.85, "rainfall": 45.0}'
```

Expected response:

```json
{
  "prob_1h": 0.45,
  "prob_3h": 0.72,
  "prob_6h": 0.89,
  "flood_alert_1h": true,
  "flood_alert_3h": true,
  "flood_alert_6h": true,
  "alert_level": "RED",
  "current_level_cm": 385.0
}
```

## API Endpoints

| Endpoint   | Method | Description                                 |
| ---------- | ------ | ------------------------------------------- |
| `/predict` | POST   | Submit sensor reading, get flood prediction |
| `/history` | GET    | Get processed history for the dashboard     |
| `/health`  | GET    | Check API status                            |
| `/reset`   | POST   | Reset prediction buffer                     |
| `/ingest`  | POST   | Private hardware upload of raw readings     |

### Supabase table contract

Create a table named `flood_readings` with these columns:

- `id` bigint generated by default as identity primary key
- `timestamp` timestamptz not null
- `station` text not null
- `water_level_cm` numeric not null
- `rainfall_mm` numeric not null
- `alert_level` text not null
- `prob_1h` numeric not null
- `prob_3h` numeric not null
- `prob_6h` numeric not null

Suggested environment variables:

```bash
DATABASE_URL=postgresql://<user>:<password>@<host>:5432/postgres
SUPABASE_HISTORY_TABLE=flood_readings
SUPABASE_INGEST_TABLE=flood_readings
INGEST_API_KEY=<private-device-key>
```

## Development Notes

### Label Generation

Flood labels are generated by looking ahead 1h, 3h, and 6h:

- `flood_alert_1h = 1` if water level reaches ≥400cm within next 1 hour

### Model Training

- Algorithm: XGBoost
- Split: 70% train / 15% validation / 15% test (chronological)
- Threshold: 40% (biased for recall over precision - better to have false positives than miss real floods)
